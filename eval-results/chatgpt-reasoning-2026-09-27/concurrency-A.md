結論は、(1) 不安全、最小完了 writer 数は 2、(2) 不安全で完了 writer 数 0 の反例がある、(3) 2 修正を同時に入れれば成功した reader の安全性は証明できるが wait-free ではない、(4) 任意の有限 \(k\) では不十分で、最小 \(2^{k-1}\) 個の完了 writer で wraparound 反例を作れます。

## 1. 2ビット `seq`、writer は完全直列化

**不安全です。** 次の全順序で reader は不正な \((2,1)\) を返します。`fetch_add` は「旧値→新値」で示します。

| # | 原子的イベント | 結果 / 直後の状態 `(seq,x,y)` |
|---:|---|---|
| 0 | 初期状態 | `(0,0,0)` |
| 1 | `R1: a=seq` | `a=0` |
| 2 | `W1(1): seq.fetch_add(1)` | `0→1`, `(1,0,0)` |
| 3 | `W2(1): x=1` | `(1,1,0)` |
| 4 | `W3(1): y=1` | `(1,1,1)` |
| 5 | `W4(1): seq.fetch_add(1)` | `1→2`, `(2,1,1)`；`writer(1)` 完了 |
| 6 | `W1(2): seq.fetch_add(1)` | `2→3`, `(3,1,1)` |
| 7 | `W2(2): x=2` | `(3,2,1)` |
| 8 | `R2: p=x` | **`p=2`** |
| 9 | `R3: q=y` | **`q=1`** |
| 10 | `W3(2): y=2` | `(3,2,2)` |
| 11 | `W4(2): seq.fetch_add(1)` | `3→0`, `(0,2,2)`；`writer(2)` 完了 |
| 12 | `R4: b=seq` | **`b=0`** |

したがって

\[
a=b=0,\qquad a\text{ は偶数}
\]

なので reader は成功扱いになり、

\[
(p,q)=(2,1)
\]

を返します。これは明らかに不正です。

### 完了 writer 数の最小性

最小は **2 個**です。

writer が直列化されているので、writer の `W1`〜`W4` の途中では `seq` は奇数です。したがって成功する試行の `R1` と `R4` は writer の途中には置けません。

`p≠q` を得るには、`R1`〜`R4` の間に少なくとも1つ writer のデータ更新が必要です。よって `seq` の増分回数は正です。一方、

\[
a=b\pmod 4
\]

なので、その間の `seq` 増分回数は正の 4 の倍数。最小は 4 回です。

1 writer は `seq` をちょうど2回増分するため、

\[
4/2=2
\]

個の writer が完了する必要があります。上の列がちょうど2個で達成しているため最小です。

## 2. `seq` は無限精度だが writer を並行実行

**これだけでも不安全です。** wraparound は不要です。

しかも reader が不正復帰する時点で、**完了 writer 数を 0** にできます。

| # | 原子的イベント | 結果 / 直後の状態 `(seq,x,y)` |
|---:|---|---|
| 0 | 初期状態 | `(0,0,0)` |
| 1 | `W1(1)` | `seq: 0→1` |
| 2 | `W1(2)` | `seq: 1→2` |
| 3 | `W2(1): x=1` | `(2,1,0)` |
| 4 | `R1: a=seq` | **`a=2`** |
| 5 | `R2: p=x` | **`p=1`** |
| 6 | `W2(2): x=2` | `(2,2,0)` |
| 7 | `W3(2): y=2` | `(2,2,2)` |
| 8 | `R3: q=y` | **`q=2`** |
| 9 | `R4: b=seq` | **`b=2`** |

よって

\[
a=b=2,\qquad a\text{ は偶数},
\]

なので reader は

\[
(p,q)=(1,2)
\]

を返します。

この時点で

- `writer(1)` はまだ `W3(1),W4(1)` をしていない
- `writer(2)` はまだ `W4(2)` をしていない

ので、**完了した writer は 0 個**です。0 未満にはできないため最小です。

原因は、writer を直列化しないと

> `seq` が偶数 ⇒ writer が更新中ではない

が成立しないことです。ここでは2個の writer がそれぞれ `W1` を済ませたため、両方とも未完了なのに `seq=2` と偶数になっています。

---

## 3. writer を同一 mutex で直列化し、`seq` を無限精度にする

この2つを**同時に**行えば、reader が成功した場合の安全性は証明できます。

writer が直列化されているため、次の不変条件が成立します。

- writer の `W1` 前または `W4` 後：`seq` は偶数
- ある writer が `W1` を済ませ `W4` をまだ済ませていない：`seq` は奇数
- 同時にその状態にある writer は高々1個

成功した reader 試行について

\[
a=b,\qquad a\text{ は偶数}
\]

とします。

`seq` は無限精度で、各 `fetch_add` は必ず値を 1 増やします。したがって `R1` と `R4` で同じ値を読んだ以上、

\[
R1\text{ と }R4\text{ の間には }seq.fetch\_add\text{ が1回もない。}
\]

さらに `R1` 時点の `a` は偶数なので、その時点で `W1` 済み・`W4` 未済みの writer は存在しません。

もし `R1`〜`R4` の間に新しい writer が `W2` や `W3` を行うなら、その前に必ず `W1` が必要ですが、それは `seq` を増加させるため `a=b` に反します。

したがって `R1`〜`R4` の間では **`x,y` は一度も書き換えられません**。

writer は直列化されており、writer の外側では状態は必ず

\[
(x,y)=(v,v)
\]

（または初期状態 `(0,0)`）です。ゆえに reader の

\[
p=x,\qquad q=y
\]

は同一の安定状態から取得され、

\[
p=q
\]

であり、その状態を reader の呼出しから復帰までの線形化点、例えば `R1` 時点に対応させられます。

### なぜ2修正の両方が必要か

- **writer の直列化だけ**：1 の 2-bit wraparound 反例で不足。
- **無限精度 `seq` だけ**：2 の並行 writer 反例で不足。

つまり両方がそれぞれ別の破綻原因を除いています。

### wait-free か

**wait-free ではありません。**

例えば各試行 \(n=0,1,2,\dots\) について、

1. 状態が `seq=2n, x=y=n`
2. reader: `R1` で `a=2n`
3. `writer(n+1)` を丸ごと実行し `seq=2n+2, x=y=n+1`
4. reader: `R2`, `R3`
5. reader: `R4` で `b=2n+2`
6. `a≠b` なので再試行

とできます。

これを writer が永久に続ければ、reader 自身は無限回ステップを実行しても復帰しません。したがって「他スレッドの動作によらず有限個の自分のステップで完了」という wait-free 性はありません。

一方、最後の writer が完了した後は異なります。以後 `seq` は一定の偶数で `x=y` も一定です。

reader がその時点ですでに古い `a` を持つ試行の途中なら、その試行は失敗し得ますが、**次の試行は必ず成功**します。最後の writer 完了後に reader が継続してステップを取れるなら、最大でも

- 現在の古い試行の残り最大3 read
- 次の成功試行4 read

の **7 個の reader 原子操作以内**に復帰します。

したがって、書込み停止後の進捗は保証されますが、wait-free ではありません。

## 4. 固定 \(k\) ビットへの拡張

**任意の有限 \(k\) では安全性を証明できません。**

法を

\[
M=2^k
\]

とします。1 writer は `seq` を2回増加させるので、完全な writer \(m\) 個では

\[
seq\mapsto seq+2m\pmod M.
\]

元の値に戻る最小の正の \(m\) は

\[
2m\equiv0\pmod{2^k},
\]

すなわち

\[
\boxed{m=2^{k-1}}.
\]

### 一般化した具体的反例

\[
m=2^{k-1}
\]

と置きます。

まず reader が

\[
R1:\quad a=0
\]

を読みます。

その後 `writer(1)` から `writer(m-1)` までを完全に実行します。すると

\[
seq=2(m-1)=2^k-2\pmod{2^k},
\qquad x=y=m-1.
\]

次に `writer(m)` を次のように割り込みます。

1. `W1(m)`:
   \[
   seq:(2^k-2)\to(2^k-1)
   \]
2. `W2(m): x=m`
3. reader `R2`:
   \[
   p=m
   \]
4. reader `R3`:
   \[
   q=m-1
   \]
5. `W3(m): y=m`
6. `W4(m)`:
   \[
   seq:(2^k-1)\to0
   \]
7. reader `R4`:
   \[
   b=0
   \]

したがって

\[
a=b=0,\qquad a\text{ は偶数},
\]

なのに

\[
\boxed{(p,q)=(m,m-1)}
\]

を返します。

\(k=1\) でも成立します。この場合 \(m=1\) で、先行 writer はなく、

\[
(p,q)=(1,0)
\]

となります。

### 必要な完了 writer 数の最小性

成功時には `R1`,`R4` とも同じ偶数値です。writer は直列化されているため、偶数値を読んだ時点は `W1`〜`W4` の途中ではありません。

不正値を得るには途中で writer のデータ更新が必要なので、`R1`〜`R4` の `seq` 増分回数は正です。それでも同じ \(k\)-bit 値へ戻るには、増分回数は正の \(2^k\) の倍数でなければなりません。最小は

\[
2^k
\]

回です。

1 writer あたり2増分なので、最小完了 writer 数は

\[
\boxed{2^k/2=2^{k-1}}.
\]

したがって、reader が任意に長く停止できるモデルでは、**どれだけ大きくても固定有限幅の `seq` は wraparound を排除できません**。安全性に必要なのは、このモデルでは writer の直列化に加えて、実質的に wraparound のない単調カウンタです。
