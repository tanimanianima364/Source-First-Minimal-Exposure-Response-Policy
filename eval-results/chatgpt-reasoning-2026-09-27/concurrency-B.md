結論は、**1: 不安全、最小2 writer 完了。2: 不安全、完了 writer 最小0。3: 2修正を同時に入れれば成功時の安全性は証明できるが wait-free ではない。4: 任意の固定 k ビットでも不十分で、反例には最小 \(2^{k-1}\) writer 完了が必要**です。

## 1. writer 直列化 + `seq` 2ビット mod 4

**不安全です。** `seq` が一周して同じ偶数値に戻るため、reader が更新を見逃せます。

初期状態：
\[
(seq,x,y)=(0,0,0)
\]

次が完全な反例です。

|順序|イベント|結果 / 直後の状態|
|---:|---|---|
|1|reader 呼出し||
|2|R1: `a = seq`|`a=0`|
|3|R2: `p = x`|`p=0`|
|4|writer(1) 呼出し||
|5|W1: `seq.fetch_add(1)`|`seq: 0→1`|
|6|W2: `x=1`|`x=1`|
|7|W3: `y=1`|`y=1`|
|8|W4: `seq.fetch_add(1)`|`seq: 1→2`|
|9|writer(1) 完了|状態 `(2,1,1)`|
|10|writer(2) 呼出し||
|11|W1: `seq.fetch_add(1)`|`seq: 2→3`|
|12|W2: `x=2`|`x=2`|
|13|W3: `y=2`|`y=2`|
|14|W4: `seq.fetch_add(1)`|`seq: 3→0`|
|15|writer(2) 完了|状態 `(0,2,2)`|
|16|R3: `q = y`|`q=2`|
|17|R4: `b = seq`|`b=0`|
|18|reader 判定|`a=b=0` かつ偶数 → **`(0,2)` を返す**|

`p≠q` なので明らかに不正です。

### 完了 writer 数の最小性

成功試行では

\[
a=b\pmod 4.
\]

R1 と R4 の間に行われた `fetch_add` の個数を \(N\) とすると、

\[
N\equiv0\pmod4.
\]

さらに R1 で `a` は偶数です。writer は直列化されているので、ある writer が W1 済み・W4 未済みなら `seq` は必ず奇数です。したがって R1 時点ではそのような writer は存在しません。

完了 writer が2個未満なら、R1 以後に発生できる `fetch_add` は最大でも

- 1 writer 完了による2回
- 次 writer の W1 による1回

の計3回です。よって \(N<4\)。

一方 \(N\equiv0\pmod4\) なので、

\[
N=0.
\]

この場合、R1–R4 間には W2/W3 も入り得ません。したがって値は安定した `(v,v)` で、不正復帰にはなりません。

よって不正復帰までに必要な完了 writer 数は少なくとも2。上の列が2で達成するので、

\[
\boxed{2}
\]

が最小です。

## 2. `seq` を無限精度にするが writer を並行実行可能にする

**これだけでも不安全です。**

問題は wraparound ではなく、複数 writer が同時に W1 を済ませると、

> `seq` が偶数なのに writer が更新途中

という状態が生じることです。

反例：

|順序|イベント|結果 / 状態|
|---:|---|---|
|1|writer(1) 呼出し||
|2|writer(1) W1|`seq: 0→1`|
|3|writer(2) 呼出し||
|4|writer(2) W1|`seq: 1→2`|
|5|reader 呼出し||
|6|R1: `a=seq`|`a=2`|
|7|R2: `p=x`|`p=0`|
|8|writer(1) W2|`x=1`|
|9|writer(1) W3|`y=1`|
|10|R3: `q=y`|`q=1`|
|11|R4: `b=seq`|`b=2`|
|12|reader 判定|`a=b=2`、偶数 → **`(0,1)` を返す**|

この時点では、

- writer(1) は W4 未実行
- writer(2) は W2 以降未実行

なので、**完了 writer は0個**です。

したがって最小値は

\[
\boxed{0}.
\]

`seq` は無限精度なので ABA はありません。それでも、2個の W1 が重なって `seq=2` になったことで、偶数判定の意味が壊れています。

## 3. writer を mutex で直列化 + `seq` を無限精度化

この2つを**同時に**行えば、reader が成功して返す値については安全性を証明できます。

成功した試行を

\[
R1,\ R2,\ R3,\ R4
\]

とし、

\[
a=b=s,\qquad s\text{ は偶数}
\]

だったとします。

### 証明

無限精度 `seq` は各 `fetch_add` ごとに厳密に1増えます。

したがって `a=b` なら、R1 と R4 の間には

\[
\boxed{\text{seq の fetch\_add は1回もない}}
\]

ことになります。

また writer は mutex により完全直列化されています。各 writer の区間

\[
W1 \; \cdots \; W4
\]

では、W1 後から W4 前まで `seq` は奇数です。

R1 で `s` は偶数なので、R1 時点で W1 済み・W4 未済みの writer は存在しません。

ここで R1–R4 間に W2 または W3 があったと仮定すると、その writer の W1 は

- R1 より前なら、R1 時点で `seq` が奇数になって矛盾
- R1 より後なら、R1–R4 間に `fetch_add` があることになり `a=b` と矛盾

です。

したがって R1–R4 間には W2/W3 もありません。よってその区間で `x,y` は不変で、直前に完了した writer の値、または初期値です。

従って

\[
p=q=v
\]

であり、その `(v,v)` は reader の呼出しから復帰まで実際に成立しています。例えば成功試行中の R2 の時点を reader の線形化点にできます。

writer 側は、例えば W4 を線形化点とすれば整合します。

### なぜ両方必要か

- **mutex だけ**、`seq` が有限幅  
  → 問1の ABA 反例。2ビットなら2 writer で一周する。
- **無限精度 `seq` だけ**、writer 非直列化  
  → 問2の反例。複数の W1 が重なり、更新途中なのに偶数になる。

したがって、この方式では2条件とも必要です。

### wait-free か

**wait-free にはなりません。**

writer が永続的に続く実行では、例えば各試行について

1. writer が W1 を実行して `seq` を奇数にする
2. writer を一時停止
3. reader に R1～R4 を実行させる
4. `a=b` でも奇数なので失敗
5. writer が W2,W3,W4 を完了
6. 次の writer が W1
7. 次の reader 試行

を無限に繰り返せます。

reader 自身は何度もステップを実行しているのに永久に復帰しないので、

\[
\boxed{\text{wait-free ではない}}
\]

です。

一方、**最後の writer が完了し、その後一切書込みがない**なら `seq` は永久に一定の偶数で、`x=y=v` も一定です。

その後に開始する reader 試行は R1～R4 の4 read で必ず成功します。writer 完了時に reader が既に古い試行の途中だった場合でも、その試行を終えた後の次の試行は必ず成功するため、writer 完了後の reader read は最大でも

\[
3+4=7
\]

回で復帰します。つまり**静止後には有限ステップで収束するが、任意の並行実行に対する wait-free 保証ではない**、という区別になります。

## 4. 固定 k ビットへの拡張

**任意の固定 \(k\ge1\) でも安全性は証明できません。**

法を

\[
M=2^k
\]

とします。

直列化された1 writer は `seq` を合計2増加させます。したがって \(m\) 個の writer が完了すると、

\[
seq\mapsto seq+2m\pmod{2^k}.
\]

元の値に戻る最小の正の \(m\) は

\[
2m\equiv0\pmod{2^k},
\]

すなわち

\[
\boxed{m=2^{k-1}}.
\]

そこで \(m=2^{k-1}\) として次を実行します。

1. R1: `a=0`
2. R2: `p=0`
3. `writer(1), writer(2), …, writer(m)` をすべて完全に直列実行
4. R3: `q=m`
5. R4: `b=0`

各 writer \(i\) のイベントは

\[
\begin{aligned}
W1 &: seq:2(i-1)\to2i-1\pmod{2^k},\\
W2 &: x=i,\\
W3 &: y=i,\\
W4 &: seq:2i-1\to2i\pmod{2^k}.
\end{aligned}
\]

最後には

\[
2m=2^k\equiv0\pmod{2^k},
\]

なので

\[
a=b=0
\]

かつ偶数です。しかし

\[
(p,q)=(0,m),
\]

したがって不正です。

必要な完了 writer 数の最小値も同じです。R1–R4 間で `seq` が同じ値に戻るには、非零なら少なくとも \(2^k\) 回の `fetch_add` が必要です。直列 writer 1個あたり2回なので、少なくとも

\[
\boxed{2^{k-1}}
\]

個の writer 完了が必要です。

したがって、ビット幅をどれだけ固定で増やしても、reader を任意に長時間停止できるモデルでは単に ABA が起きるまでの writer 数を増やすだけです。

\[
\boxed{\text{有限 }k\text{ では不可。必要なのは wrap しない seq（このモデルでは無限精度）}}
\]
