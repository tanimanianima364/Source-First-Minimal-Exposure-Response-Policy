## 結論

最小構成は、次の3要素です。

| 構成要素 | 用途 |
|---|---|
| 承認済み自動化ランナー | 毎日の定時実行、実行結果・障害情報のログ保持 |
| 1本の集計ジョブ | CSV読込み、部署別集計、検算、冪等な出力処理 |
| 既存の共有フォルダ | 入力、作業領域、確定出力を分離し、ロール単位でアクセス制御 |

インストール済みスプレッドシートは、本番処理経路には含めません。ユーザー操作が必要で、無人実行、永続ログ、再実行時の重複防止を提供できないためです。必要なら、集計結果の手動照合にだけ利用します。

## 構成イメージ

```text
CSV提供者
   │
   ▼
共有フォルダ /input
   │ 読取り
   ▼
自動化ランナー ── 実行ログを保持
   │
   ├─ 共有フォルダ /work     ランナー専用
   │
   └─ 共有フォルダ /output   確定結果
                              │
                              ▼
                         結果利用者
```

ジョブは毎日1回、専用サービスアカウントで実行します。ユーザーのログイン状態やスプレッドシート画面には依存させません。

## 再実行時の重複防止

重複防止は、ランナーの機能ではなく集計ジョブの出力手順で実現します。「同じ日付の処理を再実行しても、確定結果は1つだけ」という業務上の exactly-once を保証します。

### 1. バッチIDを固定する

実行時刻ではなく、入力CSVに対応する業務日または提供元の一意なIDをバッチIDにします。

例：

```text
2026-09-27
```

障害後の再実行でも同じバッチIDを使用します。修正版CSVを正式に再処理する場合は、`2026-09-27-r2` のように明示的な改訂IDを使用します。

### 2. 出力先を一意にする

バッチIDから確定出力先を決めます。

```text
/output/2026-09-27/
    department_totals.csv
    manifest
```

`manifest`には少なくとも次を記録します。

- バッチID
- 入力CSVのハッシュ値
- 入力データ行数
- 出力CSVのハッシュ値
- 部署数
- ジョブまたは集計仕様のバージョン
- 完了日時

CSVは部署順、数値書式、文字コード、改行形式を固定し、同じ入力から常に同じ内容が生成されるようにします。

### 3. 追記・直接上書きを禁止する

ジョブは確定出力へ直接書かず、まずランナー専用の作業領域に完全な出力を作ります。

処理順序は次のとおりです。

1. 入力CSVを読み、バッチIDと入力ハッシュを確定する。
2. 部署別集計を実施する。
3. 行数、部署数、合計値などを検算する。
4. `/work` に出力CSVとmanifestを完成させる。
5. 完成した一式を、未作成の場合だけ `/output/<バッチID>` に原子的に公開する。
6. 確定出力がすでに存在する場合は、manifestとハッシュを比較する。
   - 同一なら、書き込まず「処理済み」として正常終了する。
   - 異なるなら、上書きせず「同一バッチIDの内容不一致」として異常終了する。

出力CSVへの追記は行いません。また、単純な「ファイルが存在しなければ書く」という確認だけでは、並行実行時に競合するため不十分です。

### 4. 障害位置ごとの動作

| 障害位置 | 再実行時の処理 |
|---|---|
| 集計途中 | 不完全な作業ファイルを破棄し、最初から再集計 |
| 作業ファイル完成後、確定前 | 既存作業ファイルを検証するか、再作成して確定 |
| 確定出力公開後、成功ログ記録前 | 確定出力とmanifestを検証し、再書込みせず処理済みとして終了 |
| 正常完了後 | 確定出力を検証し、再書込みせずスキップ |

このため、確定出力の存在そのものを冪等性の記録として利用できます。

## 重要な成立条件

提供された環境説明では、共有フォルダについて明記されているのはロールベースのアクセス制御だけです。以下のファイル操作能力は明記されていません。

- 完成済みファイルまたはディレクトリの原子的な移動
- 「出力先が存在しない場合だけ作成する」という排他的作成
- 並行する2実行のうち1つだけを成功させる動作

したがって、上記の原子的な公開処理が共有フォルダ上で利用できることを検証して初めて、厳密な重複防止を満たしたと判定できます。

この機能がない場合、決定的なファイル名や上書き方式によって重複ファイルを減らすことはできますが、並行再実行を含む厳密な重複防止は保証できません。承認済み製品だけではその不足を補う別の機能がないため、その場合は全要件充足とは判定できません。

## アクセス制御

共有フォルダを少なくとも3領域に分離します。

| ロール | `/input` | `/work` | `/output` | ランナーログ |
|---|---:|---:|---:|---:|
| CSV提供者 | 作成・配置 | 不可 | 不可 | 不可 |
| ランナー用サービスアカウント | 読取り | 読書き | 作成・読取り | 書込み |
| 結果利用者 | 不可 | 不可 | 読取りのみ | 原則不可 |
| 運用担当・監査担当 | 必要に応じ読取り | 原則不可 | 読取り | 読取り |

追加の管理上の条件は次のとおりです。

- 入力CSVは「準備完了」後に変更しない。
- ランナー以外に `/work` と確定出力への書込みを許可しない。
- 結果利用者は確定済み出力だけを参照する。
- ログにCSVの明細行や機微情報を出さない。
- ランナーの管理権限と、CSV提供者・結果利用者の権限を分離する。

## 実行ログ

各実行について、少なくとも次をランナーの永続ログに残します。

- 実行ID
- バッチID
- 開始・終了日時
- 入力ファイル名と入力ハッシュ
- 読み込んだ行数
- 正常行数、除外行数、エラー行数
- 部署数
- 出力先と出力ハッシュ
- 結果ステータス  
  `SUCCESS`、`ALREADY_COMPLETED`、`CONFLICT`、`FAILED` など
- エラー内容
- ジョブバージョン

ログの必要保持期間が提示されていないため、受入前に「何日または何か月保持するか」を決定し、ランナーの保持設定に反映する必要があります。保持期間中、ランナー再起動後も検索・参照できることを確認します。

## 検証方法と合格条件

| 検証項目 | 実施内容 | 合格条件 |
|---|---|---|
| 集計精度 | 正解を事前計算した5万行CSVを投入 | 全部署の件数・金額等が期待値と一致 |
| 全体検算 | 入力全体の合計と部署別合計の総和を比較 | 定義された除外分を除き一致 |
| 無人実行 | ユーザーがログインしていない状態で定刻を迎える | ランナーが起動し、出力とログが生成される |
| 正常完了後の再実行 | 同じバッチID、同じCSVで再実行 | 出力のハッシュと更新日時が変わらず、`ALREADY_COMPLETED` が記録される |
| 確定前障害 | 作業ファイル作成中または確定直前で強制終了 | 再実行後、完全な確定出力が1組だけ存在する |
| 確定直後障害 | 出力公開直後、成功ログ前で強制終了 | 再実行で出力を書き直さず、既存出力を正常完了として認識する |
| 並行実行 | 同一バッチIDをほぼ同時に2回開始 | 1実行だけが公開に成功し、確定出力は1組だけ |
| 内容差替え検知 | 同じバッチIDで内容の異なるCSVを投入 | 既存出力を上書きせず、`CONFLICT` で停止する |
| 部分ファイル防止 | 公開処理中にプロセスを停止 | 利用者から不完全な確定CSVが見えない |
| ログ保持 | 過去の実行を保持期間内で検索 | 実行ID、バッチID、件数、ハッシュ、結果、エラーを取得できる |
| 入力権限 | 結果利用者から入力を開く | 拒否される |
| 出力書込み権限 | CSV提供者・結果利用者から出力を変更する | 拒否される |
| 作業領域権限 | 一般利用者から `/work` を参照する | 拒否される |
| 性能 | 実データ相当の5万行を処理 | 合意した日次処理時間内に完了し、次回実行に重ならない |

特に「並行実行」と「確定直後の障害」の2試験が、単なるファイル名の工夫ではなく、実際に重複防止が成立していることを確認する中心的な試験です。

以上により、原子的な公開が利用可能なら、追加製品なしで「無人定時実行・再実行時の一意な確定結果・ログ保持・入出力アクセス制御」を満たせます。原子的な公開が確認できなければ、現状の承認済み機能だけでは重複防止要件が未充足です。
