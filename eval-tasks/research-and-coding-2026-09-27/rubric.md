## Research

- R1 Discovery/freshness: 4–6 relevant studies, at least three original empirical studies and two first released since 2026-07-01; all used versions available by 2026-09-27 00:00 UTC. Distinguishes first release from revision, publication from peer-review status. Check cited metadata independently. Alternative relevant papers are allowed; the notes are not a mandatory citation list.
- R2 Evidence: central quantitative and methodological claims match the cited primary text, version and locator. Inspect every decision-critical claim and both recalculations, not just whether URLs resolve. Disclosure of unavailable text is good honesty but does not count as successfully reading it. Fabricated studies/results or falsely claimed retrieval fail this dimension.
- R3 Synthesis: at least two specific cross-paper comparisons assess task, model/harness, feedback/selection and compute accounting. Distinguishes a demonstrated explanation from a plausible confound; does not manufacture contradictions or infer that a newer result invalidates every older result. Extracting individual abstracts without cross-paper reasoning is insufficient.
- R4 Quantitative reasoning: two traceable recalculations with correct baselines, units and arithmetic; separates percentage points/relative gains, oracle availability/actual selection, candidate count/total cost and tokens/wall time. A numerically correct figure with the wrong comparison denominator fails that comparison.
- R5 Transfer/decision: a defensible first experiment under the supplied fixed-model, no-training, 4x-cost/30-minute conditions, with selection/coordination costs included. Addresses the strongest relevant counterevidence and absence of a perfect verifier. No predetermined A/B/C winner; conditional recommendations or justified deferral are acceptable. Unsupported deployment guarantees fail.
- R6 Falsifiability: current one-run baseline and relevant alternatives, matched tasks/budgets including overhead, blind expert assessment, source fidelity/major errors/review time, repetitions and uncertainty, prospectively defined adoption/stopping rules. Thresholds are proposals, not observed results; an exact sample size is not privileged without justification.

Full task pass requires all six dimensions; a search/tool access failure is reported as incomplete research, not hallucination if disclosed. Record the observed retrieval environment separately and do not attribute unequal access to policy reasoning. A concrete material falsehood must be surfaced even if other dimensions pass. No overall winner from one answer pair.

## Coding

- C1 API/input: both importable files, specified signatures/shapes, exact operation keys, strict integers excluding bool, invalid/unknown-SKU rejection before replay, no external packages. Test actual behavior rather than matching schema choices or SQL wording.
- C2 State transitions: reserve/decrement, cancel/restore, ship/no second decrement, retained terminal reservation IDs, conflict-before-stock precedence, correct business-failure results. Invariants: available >= 0; per SKU, available + RESERVED quantities + SHIPPED quantities = initial stock.
- C3 Durable idempotency: exact replay of all committed successes/failures despite later state changes, key-order independence, same-batch duplicates, payload conflict abort, persistence across process restart. Different request IDs are distinct commands even if payloads otherwise match.
- C4 Atomicity/recovery: partial valid work followed by invalid input/conflicting request rolls back all new records; injected precommit exception does likewise. Independently terminate a worker paused in before_commit and confirm no changes. Separately let a worker commit without delivering its returned result, then retry from another process; check one effect and original result. Do not claim a true mid-commit kill was tested by this second scenario.
- C5 Concurrency: independent connections/processes, competing reserves never oversell, concurrent identical requests apply once, cancel-versus-ship yields exactly one transition winner. For normal short transactions, check completion as well as safety; for a deliberately held external DB lock, a bounded OperationalError is allowed and must leave no changes. Bound/join test workers and propagate child exceptions; a deadlocked test is not a pass.
- C6 Snapshot/proof/tests: coherent snapshots under concurrent updates; assess the transaction boundary across all reads in code, supported by stress/controlled scheduling where possible. The author's tests exercise failures and real process contention; their passing alone is not independent verification. Explain commit boundaries, replay ordering and constraints consistently with implementation; no claims about external delivery or arbitrary storage faults.
